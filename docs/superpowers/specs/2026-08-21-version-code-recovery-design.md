# Android versionCode 恢复设计

## 目标

修复启动器 `1.1.3` 被错误发布为 `versionCode=1001003` 后，无法被游戏 APK `versionCode=1` 覆盖的问题，同时避免用户重新下载约 1.9 GB 游戏资源。

## 最终规则

- 正常启动器永久使用 `versionCode=1`，仅通过三段式 `versionName` 区分启动器版本。
- 游戏 APK 保持 `versionCode=1`，OBB 保持 `main.1.com.TFAC.CorssingVoid.obb`。
- 正常发布脚本拒绝任何非 `1` 的启动器 `versionCode`。
- 只有一次性迁移恢复包可以显式使用 `versionCode=1001003`，且该例外不能被用于其他值。

## 一次性迁移

1. 当前 `1.1.3` 用户覆盖更新到恢复版，应用私有数据保持不变。
2. 恢复版允许用户选择一个外部文件夹，将当前下载任务的全部已验证碎片导出。
3. 导出由前台服务执行，通知栏和底部任务栏显示当前碎片、字节和百分比。
4. 每个目标文件先写临时文件，复制时计算 SHA-256；哈希和大小均匹配后再替换正式文件。
5. 导出失败不删除源碎片、APK、OBB或已经成功导出的正式碎片。
6. 导出成功后状态回到 `ready`，现有游戏安装包仍可用。
7. 用户卸载错误版本，重新安装正常 `versionCode=1` 启动器，再通过“导入游戏碎片”恢复并安装游戏。

## 界面

- “游戏管理”增加“导出已下载碎片”。
- 仅在本机存在完整且已验证的下载任务时启用。
- 选择文件夹后立即进入 `exporting` 状态，复用全局进度栏。
- 导出完成显示“游戏碎片已导出，可以重新安装启动器”。

## 安全边界

- 不修改 Unreal 工程和游戏 APK。
- 不把签名私钥放进手机启动器。
- 不删除或移动应用私有目录中的源碎片。
- 导出前后均以清单中的文件名、大小和 SHA-256 为准。
