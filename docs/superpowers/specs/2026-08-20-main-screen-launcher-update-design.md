# Android 启动器主界面更新设计

## 目标

Android 启动器仍在启动时优先检查自身版本，但不再使用独立更新遮罩或弹窗。发现新版本、下载更新、校验安装包和等待系统安装的全部状态都在现有主界面内展示，并复用游戏下载使用的底部悬浮进度栏。

## 交互流程

1. 启动器加载后先检查启动器版本，再检查游戏状态。
2. 检查期间保留主界面，主按钮显示检查状态，不弹出新页面。
3. 发现新版本时，主按钮显示“更新启动器”，目标版本区域显示启动器目标版本。
4. 用户开始更新后，底部悬浮进度栏显示下载、校验和准备安装阶段，并展示百分比、已下载大小、总大小及可用的速度信息。
5. 更新包准备完成后，主按钮显示“安装启动器”；点击后打开系统覆盖安装界面。
6. 网络或清单检查失败时，主界面显示具体原因，主按钮提供“重新检测”。其他页面仍可进入。

## 安全边界

- 保留“必须使用最新版启动器才能通过网络下载游戏”的限制。
- 未成功确认启动器版本时，不允许开始 OSS 或 GitHub 游戏下载。
- 本地“导入碎片”不依赖网络，也不受启动器版本检查限制。
- 开发版继续跳过强制更新检查。
- 游戏下载广播不得覆盖启动器更新阶段和进度。

## 实现范围

- 删除 `App.vue` 中的启动器更新遮罩结构。
- 删除 `style.css` 中只服务于该遮罩的样式。
- 让主按钮、主界面提示和底部进度栏完整覆盖启动器检查、下载、校验、待安装及安装中的状态。
- 保留现有原生下载、SHA256 校验、未知来源安装权限和覆盖安装逻辑。
- 调整集成测试，验证不存在独立遮罩、更新状态留在主界面、进度栏可见，以及网络游戏下载保险仍然生效。

## 验证

- 先增加会失败的集成测试，再修改界面实现。
- 运行 Android 启动器前端全量测试和 Vite 构建。
- 运行 Gradle 原生单元测试，确认桥接与更新服务未回归。
- 本轮不修改 Unreal 项目，也不重新打包游戏。
